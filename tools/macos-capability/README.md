# Disposable macOS capability job

This manual workflow prepares one new standard GitHub-hosted macOS ARM64 VM and tests bounded platform/display/headed-blank-page/loopback/IPC/known-owned-group capabilities. It runs no product matrix, Copilot install, benchmark, history sampling, scoring or ranking. The existing feasibility matrix remains headless and stopped. The old local unrecorded grandchild's closure remains unknown.

Dispatch is main-only and requires an exact expected commit equal to the workflow's actual `github.sha`. Source review and explicit dispatch authorization must precede any execution. Repository metadata/environment checks are admission controls; an independent original GitHub run/job/commit/artifact chain is still required for later authentication. The standard public runner has documented free compute, but organization restrictions and artifact storage remain separate unknowns. No spending, runner-group or service policy changes are made.

The workflow uses current repository locks, Playwright1.64.0 and exact Node24.20.0. Runtime admission additionally rejects a different actual Node version, and records actual Node/V8 versions. The full regular Chromium is installed; system Chrome and a headless-shell substitution are not admitted. The locked browsers.json Chromium revision/version are labeled declarations; actual browser.version() and executable file identity are separate observations, and no actual build revision query is claimed. No cache or automatic retry is configured. Native compilation, SDK/process/display queries and browser launch occur only inside the prospective hosted job. Local checks are pure tests, syntax and types. The 1280×800 headed blank-page viewport is a new explicit capability cohort, not alignment with any capture.

Before queries, actual `uname -v` selects the matching official Apple XNU source tag. Bounded original primary-source downloads are pinned, and the two previously audited public `proc_listpids` function bodies must match exact source digests. A missing/changed body fails unavailable rather than assuming zero return means absence. The helper is compiled from this checkout using the actual remote clang/SDK; its binary, headers and source are pinned there. Struct sizes, offsets and status macros are emitted by that compiled SDK, not copied from a local binary or private manifest. A returned zero with fresh errno0 can establish only a complete observed scoped group snapshot under those semantics.

Each of the two original primary-source requests retains its exact matching-tag URL, loop index, fetch-call/settlement state and original HTTP status/`ok` before the assertion. Dispatched URLs are limited to4096 UTF8 bytes; no shortened URL is requested and no alternate tag is tried. A failed response body is independently cancelled within the original preparation deadline; original read, cancellation and release-lock failures remain ordered, including falsy values. Reader EOF and lock release precede source digest/publication. A completed first source remains in the bounded attempt ledger if the second request fails. Public body cancellation or EOF records that operation's settlement, not teardown of pooled connections.

The parent records `caseSpawnAttempted` immediately before the original case spawn call, including a synchronous throw. An explicitly unattempted case with no contradictory PID/IPC/group/resource facts reports `failed-preparation-case-not-attempted`, capability unavailable and case closure `not-applicable-case-not-attempted`; the command still exits nonzero. Missing/contradictory markers do not qualify. Preparation operation settlement separately requires terminal original direct-command handles, settled public fetch/body operations, pending0 and final source closure. The receipt refreshes this state after final source checks. **Overall resource closure remains unknown**, even when these public operations settled: no pool socket, preparation descendant or host-clean claim follows. Every actually attempted case retains the existing strict scoped IPC/group/resource closure requirements. The first hosted failure and old local grandchild uncertainty are not retrospectively rewritten or promoted.

Public CoreGraphics APIs report the current Quartz session and bounded active-display metadata. `CGSessionCopyCurrentDictionary` is released; usernames/full session dictionaries are not retained. Missing session, ambiguous count, unsupported SDK or nonfinite dimensions stop the capability attempt. Page visibility/focus and two chronological real rAF callbacks are qualitative capability observations only. They establish neither a physical display refresh rate nor measured FPS.

The original application spawn wrapper is installed before dynamic Playwright import. It delegates once with the original receiver/arguments/options and returns the original ChildProcess/EventEmitter. Errors are observed through `errorMonitor`. SDK helpers use a separately captured original spawn and are not recursively registered. Original PID/PPID/UID/session/group/birth facts are captured before launch promises complete; private Playwright process fields and process-name/global PID scans are prohibited.

The code never calls a process signal or kill API. Original public Playwright close may internally force a browser process; its original exit signal is retained and cannot qualify as supported capability. Public independent page/context/browser/server closes, original IPC flush/disconnect, case exit+close and actual bounded empty snapshots of every observed owned group are required. Every admitted parent and child helper attempt is included in exit+close assessment; missing/malformed child ledgers remain unknown. Publication failure reports the full independent scoped closure status, rather than deriving it from the case's close event alone. This is knowledge about those original handles/groups, not proof that arbitrary escaped descendants or all system processes are absent.

A hung or unknown resource stays owned and fails uncontained. A single original parent start fixes the 60s acquisition boundary and its existing 10s closure/report allowance. An independently armed acquisition timer sends only a matching private IPC stop; it sends no OS signal. The child acknowledges actual acquisition before cleanup, without resetting either deadline. Closure, final source checks and publication may use only the original 70s endpoint; expiry cannot promote a late successful capability. If that endpoint is exhausted, only a bounded durability-unavailable log is possible. These smoke boundaries never extend native60/30/10 leases. The whole job has a separate12minute preparation/exposure timeout. Job timeout/cancellation is not original close proof, may prevent receipt upload, and never authorizes continuation or a favorable result. At most one small one-day receipt artifact is attempted; no forced cleanup or guessed PID is permitted.

The original HTTP ClientRequest is adopted before awaiting response completion, with agent reuse disabled, bounded response bytes and its actual close event joined independently from server/page/context/browser closes. Capability availability and observed scoped closure are separate receipt fields: an unsupported Quartz session may remain unavailable while every actually created known-owned handle/group is proven closed. Missing identities, errors in observation, unresolved operations, missing IPC/close facts or unknown group envelopes cannot receive that scoped closure status. The status never proves absence of arbitrary unobserved descendants.

Every SDK stdout/stderr stream retains at most its first64KiB before accumulation, with exact observed/retained/omitted byte counts and base64 encoding status. Timeout, overflow or invalid UTF8 cannot erase that bounded original diagnostic prefix or turn it into admitted helper JSON. Case stdout/stderr share a combined64KiB diagnostic prefix. At most256 queries and64 application spawns are admitted. Larger/partial authority fails unavailable rather than silently truncating it into a complete claim. Source hashes are rechecked after the attempt. A failure during publication retains whatever bounded log is possible and explicitly leaves durability unavailable.

## Separate macOS15 source discovery

The manual `macos-source-availability.yml` workflow performs metadata and exact source discovery only on a new standard GitHub-hosted `macos-15` runner. The standalone tool admits only actual Darwin ARM64, macOS15/Darwin24 and Node24.20.0. Before checkout, the workflow requires `cacheplane/chat-ui-bench`, `refs/heads/main` and a 40-character lowercase hexadecimal `expected_sha` equal to the workflow's actual `github.sha`; checkout uses that exact SHA. It performs no dependency installation, audit, tests, SDK compilation, browser launch or native capability attempt. The original capability workflow and first macOS26 failure receipt stay unchanged.

Discovery uses the complete unambiguous XNU tag extracted from original `uname -v` output and requests only the two maintained Apple source paths at that exact tag. Both audited function bodies must match their maintained exact digests. Missing tags, unavailable sources or mismatched bodies fail source availability; there is no alternate tag, redirected source or source fallback. A first unsuccessful request stops discovery. Successful discovery grants no native execution permission, gate bypass, benchmark or scoring admission. Native capability, SDK, browser, case and matrix execution remain unattempted; native dispatch and scoring remain false, and `overallResourceClosure` always remains `unknown`. Observed public operation settlement is separate from host, socket or fetch-pool closure.

One original script start fixes the absolute 60-second acquisition boundary and 70-second cleanup/report endpoint. No command, request or cleanup resets those deadlines. Unresolved operations remain unknown; the tool does not signal processes or claim deterministic termination at 70 seconds. The workflow's separate five-minute timeout bounds job exposure, and timeout or cancellation may prevent artifact upload without establishing original closure. Actual Git HEAD equality is checked; this is no claim that the whole working tree is clean. Before/after source facts cover only the new workflow, standalone tool, pure test and this README, not the entire repository or executed dependency graph. The recorded workflow job key is not the GitHub API job ID.

At most one original artifact is attempted with one-day retention. Its exclusive run/attempt directory contains only `receipt.json` and up to two completed original sources, `primary-0.c` and `primary-1.c`. The compact receipt including its newline is bounded to 64KiB; each original source is bounded to 256KiB, for at most 576KiB of raw artifact payload. A receipt records provisional discovery and `publicationStatus: pending-external-authentication`; its candidate status alone is not final authority. After original publication, readback, close and output identity checks, the tool emits a separate terminal witness prefixed `MACOS_SOURCE_AVAILABILITY_TERMINAL `, bounded to 4KiB. A later failure must remain unavailable and nonzero even if earlier receipt bytes say source-available. Original terminal settlement and independent timer teardown are checked before a favorable exit; a witness printed earlier remains provisional and is revoked by a later deadline, pending-operation, callback or teardown failure. Only null/undefined public writer callback values count as success, and task rejection observations are not labeled as late unless timing proves it.

Root review separately authenticates the actual original run, API job, main SHA, workflow bytes, runner image setup log and artifact chain, and reconciles the final artifact with the original command exit, outer stdout/stderr and close evidence and terminal witness. Local pure tests do not authenticate a hosted run. Even an authenticated source-available result permits only review of a separately authorized future native capability design; the old macOS26 failure and unknown native grandchild closure remain unchanged.
