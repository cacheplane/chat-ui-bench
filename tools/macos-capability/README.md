# Disposable macOS capability job

This manual workflow prepares one new standard GitHub-hosted macOS ARM64 VM and tests bounded platform/display/headed-blank-page/loopback/IPC/known-owned-group capabilities. It runs no product matrix, Copilot install, benchmark, history sampling, scoring or ranking. The existing feasibility matrix remains headless and stopped. The old local unrecorded grandchild's closure remains unknown.

Dispatch is main-only and requires an exact expected commit equal to the workflow's actual `github.sha`. Source review and explicit dispatch authorization must precede any execution. Repository metadata/environment checks are admission controls; an independent original GitHub run/job/commit/artifact chain is still required for later authentication. The standard public runner has documented free compute, but organization restrictions and artifact storage remain separate unknowns. No spending, runner-group or service policy changes are made.

The workflow uses current repository locks, Playwright1.64.0 and exact Node24.20.0. Runtime admission additionally rejects a different actual Node version, and records actual Node/V8 versions. The full regular Chromium is installed; system Chrome and a headless-shell substitution are not admitted. The locked browsers.json Chromium revision/version are labeled declarations; actual browser.version() and executable file identity are separate observations, and no actual build revision query is claimed. No cache or automatic retry is configured. Native compilation, SDK/process/display queries and browser launch occur only inside the prospective hosted job. Local checks are pure tests, syntax and types. The 1280×800 headed blank-page viewport is a new explicit capability cohort, not alignment with any capture.

Before queries, actual `uname -v` selects the matching official Apple XNU source tag. Bounded original primary-source downloads are pinned, and the two previously audited public `proc_listpids` function bodies must match exact source digests. A missing/changed body fails unavailable rather than assuming zero return means absence. The helper is compiled from this checkout using the actual remote clang/SDK; its binary, headers and source are pinned there. Struct sizes, offsets and status macros are emitted by that compiled SDK, not copied from a local binary or private manifest. A returned zero with fresh errno0 can establish only a complete observed scoped group snapshot under those semantics.

Public CoreGraphics APIs report the current Quartz session and bounded active-display metadata. `CGSessionCopyCurrentDictionary` is released; usernames/full session dictionaries are not retained. Missing session, ambiguous count, unsupported SDK or nonfinite dimensions stop the capability attempt. Page visibility/focus and two chronological real rAF callbacks are qualitative capability observations only. They establish neither a physical display refresh rate nor measured FPS.

The original application spawn wrapper is installed before dynamic Playwright import. It delegates once with the original receiver/arguments/options and returns the original ChildProcess/EventEmitter. Errors are observed through `errorMonitor`. SDK helpers use a separately captured original spawn and are not recursively registered. Original PID/PPID/UID/session/group/birth facts are captured before launch promises complete; private Playwright process fields and process-name/global PID scans are prohibited.

The code never calls a process signal or kill API. Original public Playwright close may internally force a browser process; its original exit signal is retained and cannot qualify as supported capability. Public independent page/context/browser/server closes, original IPC flush/disconnect, case exit+close and actual bounded empty snapshots of every observed owned group are required. Every admitted parent and child helper attempt is included in exit+close assessment; missing/malformed child ledgers remain unknown. Publication failure reports the full independent scoped closure status, rather than deriving it from the case's close event alone. This is knowledge about those original handles/groups, not proof that arbitrary escaped descendants or all system processes are absent.

A hung or unknown resource stays owned and fails uncontained. A single original parent start fixes the 60s acquisition boundary and its existing 10s closure/report allowance. An independently armed acquisition timer sends only a matching private IPC stop; it sends no OS signal. The child acknowledges actual acquisition before cleanup, without resetting either deadline. Closure, final source checks and publication may use only the original 70s endpoint; expiry cannot promote a late successful capability. If that endpoint is exhausted, only a bounded durability-unavailable log is possible. These smoke boundaries never extend native60/30/10 leases. The whole job has a separate12minute preparation/exposure timeout. Job timeout/cancellation is not original close proof, may prevent receipt upload, and never authorizes continuation or a favorable result. At most one small one-day receipt artifact is attempted; no forced cleanup or guessed PID is permitted.

The original HTTP ClientRequest is adopted before awaiting response completion, with agent reuse disabled, bounded response bytes and its actual close event joined independently from server/page/context/browser closes. Capability availability and observed scoped closure are separate receipt fields: an unsupported Quartz session may remain unavailable while every actually created known-owned handle/group is proven closed. Missing identities, errors in observation, unresolved operations, missing IPC/close facts or unknown group envelopes cannot receive that scoped closure status. The status never proves absence of arbitrary unobserved descendants.

Every SDK stdout/stderr stream retains at most its first64KiB before accumulation, with exact observed/retained/omitted byte counts and base64 encoding status. Timeout, overflow or invalid UTF8 cannot erase that bounded original diagnostic prefix or turn it into admitted helper JSON. Case stdout/stderr share a combined64KiB diagnostic prefix. At most256 queries and64 application spawns are admitted. The entire compact receipt—including source, platform, commands, original envelopes and lifecycle sections and its final newline—is at most256KiB. Larger/partial authority fails unavailable rather than silently truncating it into a complete claim. Source hashes are rechecked after the attempt. A failure during publication retains whatever bounded log is possible and explicitly leaves durability unavailable.
