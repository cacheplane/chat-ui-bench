# Controlled H100 observer diagnostic

After `npm ci`, run `npm run test:h100-observer` on Node 24.x on Linux or
macOS. No build, browser, Python, or downloaded command is required. The command
executes 65 serial functional subjects against the installed, pinned original
virtual core and 39 reversible instrumented variants. These subjects are counted
separately from Vitest. `npm run test:h100-observer:portability` runs the separate
runtime, output, relocation, drift, and process cleanup controls; CI runs both.

This is controlled core functional evidence. Qualification, native GO,
performance, scoring, and ranking authority are all false. Warm readiness, live
React/group/DOM/actual-owner mapping, external Map mutation continuity, and FPS
are unavailable. Passing does not admit a benchmark or establish production
readiness.

The runner resolves the checkout from its own module URL and uses
`process.execPath`. Runtime metadata records actual Node/V8 versions, platform,
architecture, and executable path as provenance, without claiming an exact
private Node binary attestation. Unsupported runtime/platform and source/base
drift refuse before vendor execution. The ten-file registry pins both source
and package metadata. The frozen 25,223-byte legacy observer retains its SHA-256
`b24787211944d896a02f7856bec7350e699c3e670301ed9a57f68ef3bf7806fc`.
The study module is derived by exactly two guarded substitutions: work 32,768
to 393,216 and its detail kind. No second observer algorithm is maintained.

Default output uses a unique `h100-observer-*` temporary parent containing an
exclusively created `run` child. The JSON result prints its location. Optional
`npm run test:h100-observer -- --out /absolute/normalized/absent/path` exclusively
creates that absent directory; existing outputs are refused without overwrite
or deletion. `npm run test:h100-observer -- --preflight` validates sources and
derivation in memory without vendor imports or output creation. No source-root,
observer URL, profile, or executable override is accepted.

All generated study, fixtures, streams, records, and receipts are beneath that
run directory. Bounds remain 120 seconds for the complete run including
finalization, five seconds per functional subject, 1 MiB per child stream,
40 variants, 96 files, 8 MiB total, and 262,144 bytes per rendered detail.
The generated study is validated before import. Original process exit and close
must both be `[0, null]`; process-group absence, stream EOF/close, and retained
file fsync/close/readback are checked. A surviving group is killed with bounded
cleanup and the run refuses. Native reflection, JSON, and synchronous file
operations cannot be preempted; cleanup never extends admission past the
original deadline. Windows closure is unsupported.

Four fresh frozen records retain work totals 143,170 at entry, 231,552 for the
actual publication argument, 297,696 after publication returns, and 363,840
after disposal. The exclusive argument writer settles the original publication
promise before the independent waiter. The exact 363,846 configuration succeeds;
363,845 refuses its final 66,144-unit copy with 66,143 remaining and 297,702
already spent. The legacy 32,768 control retains its original refusal. Earlier
observed copies remain historical after disposal and are never promoted.

The receipt inventories files present before receipt creation; verification
inventories files present before verification creation. To avoid a recursive
self-hash, the final JSON console result inventories **every** generated file,
including `verification.json`, after creation and within the original deadline.
Every inventory enforces the same limits. CI logs remain outside bounded run
output. CI preserves diagnostic and separate portability outputs plus logs on
success or failure for seven days. Temporary outputs are retained for inspection.
