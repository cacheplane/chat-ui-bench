# Warm chronology preparation source controls

Run with Node 24 after the repository's locked `npm ci`:

```sh
node tools/warm-chronology-preparation/run.mjs --test --out /absolute/new-output-directory
```

The output directory must not exist. The runner retains complete test stdout, stderr and a receipt with source hashes, before/after identity checks, child exit and stream closure. It works from any working directory when given the absolute runner path. CI preserves these outputs on success and failure. It accepts no browser, live capture or alternate source arguments.

This is a **Node-only source preparation model**. It uses `node:util` to reject proxies before reflection and accepts owned data fixtures. The formatter is not installed in a browser observer. The source resolver verifies the existing functional tool's fixed installed dependency pins; it extracts the exact original virtual-core range declarations rather than importing temporary evidence or copying an external source tree. Missing or changed installed bytes refuse before evaluation.

The baseline formatter allows 16 range records and 448 event records, at most 464 records and 49,152 ASCII bytes. Complete sample range/event witnesses are 375/85 bytes, dominated by conservative 377/88 and executable 384/96 limits. Pure selector validation uses canonical 100-row data, at most six candidates, 24 original range calls and 12 targets. It never measures, resets caches, renews origins or writes observer state. Cached rows without historical origin cannot become prospective first measurements merely by being visited.

The logical source allocation is 1,179,648 chronology units plus 917,504 selector units, retaining the same 2,097,152 total. Current inclusive bounds are 1,120,768 and 434,792. These are source-unit reservations, not native CPU measurements or a runtime integration claim. The unchanged preparation algorithm is checked by exact hash and current source census; original callbacks are checked for return, read and throw identity.

All results keep `fullWarmReady` and `nativeGO` false; FPS is unavailable. A prepared structural itinerary proves neither the actual browser baseline nor eventual full historical coverage. The E08 production hook, browser-owned-locals boundary, queue lifetime/reference peak, whole runtime wrapper and current binding fences require separate reviewed integration. The tests retain the known cached-without-origin counterexample through a test-only reverse predicate, without importing historical files.
