# Renderer presentation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add validated headed, phase-local `rendererVisualUpdateFps` using pinned Chromium renderer presentation feedback, preserving 1.0.0 artifacts and all correctness gates.

**Architecture:** Reuse the page CDP session for production tracing, record real target/frame evidence, and bracket every scored phase instance with unique trace marks. A small original offline parser resolves topology, pairs whole-trace renderer frames, and joins presentation feedback before filtering exact phase intervals. Structured per-phase results are separate from existing scalar metrics and aggregate only within matching phase, version, mode, and environment identities.

**Tech Stack:** Node 24+, npm 11+, TypeScript, Zod, Vitest, Playwright 1.64.0 and its pinned Chromium, existing npm workspaces.

## Locked interfaces and arithmetic

1. Keep artifact `schemaVersion: 1`, suite `0.1.0`. New collector/analyzer versions are `1.1.0`. Explicit accepted raw version pairs are `(collector 1.0.0, capture analyzer 1.0.0)` and `(1.1.0,1.1.0)`; manifest/evidence/invocation collector identities must agree. New analysis outputs identify analyzer 1.1.0 regardless of input. Unknown/mixed versions fail; old 1.0.0 presentation remains unavailable even if events happen to look parseable.
2. Add optional `evidence.trace.presentation` strict evidence: capability `rendererVisualUpdateFps`, contractVersion `1.1.0`, sessionTarget `page`, actual targetId, appURL, actual Page.getFrameTree result, frame-tree capture point `before-tracing`, isolatedBrowserProcess/singleWorkloadPage booleans. Declare all categories in existing `trace.categories`, adding `disabled-by-default-devtools.timeline.frame`. Keep complete/lossReason semantics. Browser revision comes from existing environment capture, never a synthesized pin. Require actual target info and frame tree; missing or unsupported topology yields explicit unavailable capability, not fabricated metadata.
3. New marks: `bench:<repetition>:phase:<instanceId>:start` and `...:end`; `instanceId` is a repetition-local monotonically increasing integer string. Each `phase` observation gains `instanceId/startMark/endMark` in data; `phase-end` records same identity. Keep existing phase records and legacy marks unchanged for stall alignment. Score only streaming-auto-follow, composer-input, gesture-scroll, return-to-bottom. Closing active scored phase is idempotent, emits its unique end mark/observation once, and happens before Tracing.end; it does not pretend validation began during trace capture.
4. Add optional `runMetrics.rendererPresentation` with `{status:'unavailable',reason}` or `{status:'available',value:{scope:'target renderer visual updates',phases:[...]}}`. For collector 1.1.0 always emit it. Each phase contains phase, instanceId, startUs/endUs/durationUs, target frameId/PID/TID, boundaryExcludedPairCount and nonPresentedPairCount plus availability-bearing `rendererVisualUpdateFps` and presentation intervals. FPS availability contains numeric value, unit `updates/s`, evidence and explicit numerator/denominatorUs. Intervals availability contains distinct chronological feedback timestamps, consecutive interval values in trace microseconds, median/p95/max with unit `us`. Use nearest-rank p95 (`sorted[ceil(0.95*n)-1]`), ordinary midpoint median. Zero eligible feedback makes both unavailable; one delivery gives available FPS but unavailable intervals. No phase-local numeric FPS/interval data survives invalid/failed-run gates. Strict Zod refinement enforces this even on nested outputs. Keep generic `metrics.presentationIntervalMs` unavailable with reason directing readers to scoped phase output; never fill it with an arbitrary whole-run rate.
5. New report field `presentationGroups` groups by `environmentIdentity(manifest)` plus phase and phase instance ordinal; aggregate phase rates/summary statistics only across that matching identity. Never aggregate phases together or average rates into a whole-run score. Preserve sample/valid/invalid/failed/unavailable counts and reasons. Existing scalar metrics, transport-clock limitations, calibration conclusions and retention behavior remain intact.
