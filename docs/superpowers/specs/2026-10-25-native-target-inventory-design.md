# Maintained native target inventory design

Date: 2026-10-25. Status: amended implementation contract after discovery of the pinned CSV renderer defect; independent review required before further implementation. Earlier prototype passes using permissive quote handling do not satisfy this amended contract. Base: `19af098698c31ad69097185f81fbd4cc2e15bb84`, following the Perfetto 59.1 pin upgrade (PR 147). This document authorizes no capture, acquisition, metric calculation, or ownership qualification.

## Purpose and decision

Add the smallest maintained diagnostic that exposes retained target, frame, layer, reporter and graphics evidence through the existing pinned Perfetto importer. Recommend a third fixed SQL policy, `target-inventory-v1`, selected only by explicit API/CLI entrypoints. It exports facts for later evaluation; it does not evaluate target ownership, clock admission, continuous lifetime, exclusivity or frame population.

Alternatives considered:

1. **Existing importer with fixed SQL (chosen):** reuses official version/pin checks, imported annotations/context, output bounds and process handling. It is the smallest maintained change and needs no new decoder.
2. **Extend V7 to V8:** appropriate only if a later evaluator requires canonical packet/field byte anchors, raw interning/reset semantics or clock state. It would require a new decoder contract and much larger fixtures; defer it. Keep existing V6/V7 behavior intact.
3. **Standalone wire parser:** reject. It duplicates raw decoding, annotation/interner/reset rules and correspondence work already handled by existing tools. Exploratory scripts remain research.

## Fixed SQL contract

Include `chrome.graphics_pipeline`. Define a private selected-slice view once, with exact-name membership in these eight families or the validated caller phase literals:

`SetLayerTreeId`, `TracingStartedInBrowser`, `FrameCommittedInBrowser`, `FrameDeletedInBrowser`, `ProcessReadyInBrowser`, `BeginFrame`, `PipelineReporter`, `Graphics.Pipeline`.

The SQL source contains exactly one `__PHASE_LITERALS__` occurrence, in the view predicate. Reuse the runner's existing 2..16 distinct literal validation, byte/control-character limits and single-quote escaping. If a phase equals a fixed family, select each slice once using one OR/IN predicate. Do not construct multiple scope copies, use LIKE/prefix matching, filter by phase time or infer a target. Use repository-compatible Perfetto view syntax; the local SQLite test removes only the module include and, if necessary, the `PERFETTO` view keyword.

Emit exactly these seven SELECT result tables, in this order. View creation and module inclusion are setup statements, not result tables:

1. **Fixed family counts:** columns `name, event_count, arg_set_count`; enumerate all eight names and LEFT JOIN slices, including zero counts. `COUNT(slice.id)` and `COUNT(DISTINCT slice.arg_set_id)`; group/order by name. Counts are inventories only. No phase count table is needed; all literal phase rows are retained below.
2. **Selected slice context:** `id, ts, dur, name, track_id, track_name, arg_set_id, utid, tid, upid, pid, process_name, thread_name, track_name_is_null, process_name_is_null, thread_name_is_null`. LEFT JOIN `track` and `thread_or_process_slice`; preserve NULL context and each original slice. Order `ts, id`. The emitter PID is context, never a substitute for an argument PID.
3. **Selected arguments:** `slice_id, name, arg_set_id, arg_present, flat_key, key, value_type, int_value, string_value, real_value, flat_key_is_null, key_is_null, value_type_is_null, int_value_is_null, string_value_is_null, real_value_is_null`. LEFT JOIN args by arg_set equality; `arg_present` is `a.arg_set_id IS NOT NULL`, not a nullable key test. Export every argument for every selected slice, including graphics/reporters and phase marks. Preserve unmatched placeholder rows and matched all-NULL-key rows distinctly. Order by slice timestamp/id then flat_key/key/value_type/int_value/string_value/real_value. Do not DISTINCT or aggregate these rows; shared arg_sets fan out once for each referring slice. Identical duplicate rows remain duplicated; their relative order is immaterial.
4. **Complete grouped keys/types:** `name, flat_key, key, value_type, arg_occurrence_count, slice_count, flat_key_is_null, key_is_null, value_type_is_null`; group/order by name/flat_key/key/value_type over the same selected scope with LEFT JOIN args. Use `COUNT(a.arg_set_id)` for matched occurrences and `COUNT(DISTINCT s.id)` for represented slices. An unmatched slice contributes zero occurrences; a matched NULL-key argument contributes one. Mixed NULL groups retain both facts.
5. **Nonzero stats:** `name, idx, severity, source, value`, `WHERE value != 0`, ordered by name/idx.
6. **Trace bounds:** `start_ts, end_ts`, complete bounds table, ordered by start/end.
7. **Normalized first-display mapping:** `surface_frame_trace_id, display_trace_id`, all rows from `chrome_surface_frame_id_to_first_display_id`, ordered by both IDs. This is the pinned module's normalized first-display mapping, not a claim of every display or target membership.

### Pinned renderer and text projection contract

The exact [59.1 CSV formatter source](https://github.com/google/perfetto/blob/1e9c61e9844affd7dccd3d42d9ea9f3a3d10cf6d/src/trace_processor/shell/csv_result_formatter.cc) shows `FormatRow` wrapping strings in double quotes without doubling interior quotes. The retained source `/private/tmp/target-v59-csv_result_formatter.cc` has SHA256 `7dc89d78b72f2333b0652ad6b62d154e641a5a8c916d5c32be0f7798b6994733`. An actual official target smoke output with a quoted value was rejected by strict Python CSV parsing. A limited interior-quote heuristic used by the earlier 39-test prototype is rejected as a solution; preserve those logs separately as superseded evidence.

Compensate only in final TEXT projections of the new SQL policy: `REPLACE(s.name, '"', '""') AS name`, and the corresponding expression for every possibly dynamic text field. The fixed renderer then wraps these projected strings to produce standard CSV quoting. Keep seven schemas and original column aliases. Apply the projection to selected slice names and track/process/thread names; argument slice names, flat_key, key, value_type and string_value; grouped name/flat_key/key/value_type; stats name/severity/source. Fixed-count names may use the same projection uniformly. Numeric columns and explicit NULL flags stay unmodified. `REPLACE(NULL, ...)` remains NULL. Do not use a hex/custom codec, new headers/profile, changed executable or output postprocessor.

WHERE, JOIN, GROUP BY and ORDER BY must use raw, qualified input columns, never quote-doubled aliases; escaping is a final presentation transform only. For example, stats uses `FROM stats st ... WHERE st.value != 0 ORDER BY st.name, st.idx`, while projecting `REPLACE(st.name, '"', '""') AS name`. Do the same qualification for names/keys in other tables; otherwise an escaped alias could silently change ordering. Preserve phase validation/substitution and scope membership on original text.

The smoke module alone contains a strict standard CSV record parser. It accepts doubled quotes, embedded comma/LF/CRLF, quoted empty fields, and record separators outside quoted fields. Blank records separate result tables only outside quotes; embedded blank lines belong to their field. It rejects interior bare quotes, characters after a closing quote other than delimiter/record end, and truncated quoted fields. It never guesses whether a quote was literal and never converts integer cells through Number. The runtime importer continues retaining original stdout without parsing or repair.

SQLite semantic tests observe the pre-render SQL projections: a source `left",right` becomes `left"",right` in a projected text cell. Assert that intentional transformation, then separately assert the full pinned-rendering/strict-parser round trip returns the original processor-visible text. Official semantic smoke must independently demonstrate that round trip; changing expected payloads to accept quoted corruption is forbidden. Keep red evidence of strict rejection before SQL compensation.

SQL numeric IDs, timestamps and int/uint argument values stay in integer columns; never cast them to REAL. Preserve exact original stdout bytes as the canonical export; no JavaScript Number conversion or JSON numeric reserialization of 64-bit values. Semantic tests parse CSV cells as strings or compare BigInt where appropriate. `value_type` distinguishes signed/unsigned/bool representations sharing `int_value`; do not reinterpret storage as a new ID type. Explicit NULL flags distinguish missing values from literal string `[NULL]`; empty string remains a value. REAL cells preserve the processor's decimal rendering, which can round, and cannot establish producer-double identity or clock evidence. The pinned SDK's C-string rendering and text decoding leave embedded NUL and malformed UTF-8 unsupported for round-trip claims. Even supported text is processor-visible text, not attestation of producer-wire byte equality.

`slice_id`, `arg_set_id`, tracks and process/thread IDs are scoped to this import and its input/processor/SQL hashes. They are not raw packet offsets, global identities, generation boundaries, or automatically aligned to another import. Do not add packet-anchor fields this SQL cannot supply.

## Safety and failure semantics

Reuse without weakening: fixed 59.1 exact version/RPC text and platform SHA256 pins; unsupported-platform rejection; trace <=32 MiB and executable <=64 MiB; explicit trace length/hash; one-link regular files, nofollow/nonblock opens and identity/hash bookends; original executable process and original pipe handling; max 60 seconds per version/query; stdout <=256 KiB and stderr <=64 KiB; fresh exclusive output directory and exclusive artifact writes. Keep exact executed/source SQL hashes, subprocess bytes/hashes and status/error records.

No LIMIT, sampling, successful prefix, graph-summary replacement or cap increase. A complete export exceeding the existing cap fails as a whole and retains bounded bytes/bookends. Empty tables, absent families, NULLs, wrong types, conflicting values and ambiguous lifetime are legitimate diagnostic facts, never authority promotion. Import success means only that bounded execution completed normally with unchanged admitted input identities. Original exit zero, normal EOF/close and no forced stream destruction remain required.
