# Same-trace clock-3 interval diagnostic design

Date: 2026-10-25. This document records the reviewed design. The original design pass performed no implementation, installation, capture, trace execution, interval calculation or rate calculation; implementation checkpoints are recorded in the companion plan.

## Purpose and boundary

Add one opt-in diagnostic that reports the exact difference between two named recorded UserTiming instants in the same supported builtin MONOTONIC clock-3 domain. The output field is `traceIntervalNs`, a decimal integer string on success and null on rejection. Generic `durationNs` stays null. This is neither a JavaScript `PerformanceMark.startTime` interval nor evidence of physical elapsed time, action latency, renderer work, presentation latency, frame interval, or native FPS. Clock admission, target/lifetime, presentation, population, metric, performance, scoring, ranking, evaluation, native support, and FPS authority remain false, unavailable, unestablished, or not_evaluated as appropriate.

The user authorized autonomous design/build/review work. This document stops at design and plan for independent review by the coordinating agent. No commit or PR is created in this pass. Base: `308751ad7b483db78932a79d7cea8d7e295769b2`, with PR 147 merged. Post-merge main CI was pending when the design was dispatched and subsequently passed all seven checks before implementation verification.

## Evidence and alternatives

Read the paired Markdown/JSON research and mark-encoding audit at `/private/tmp/chat-ui-bench-native-stock033-b69dadc-a-phase-clock-research` and `/private/tmp/chat-ui-bench-native-stock033-b69dadc-a-mark-encoding-audit`. They describe a 208730-byte retained input with SHA256 `a7b8dd7230bd33a6c0e78c497c506fd9e58bf20f0c457eb90cc5e9d0264de4d8`, two explicit packet-clock-3 marks on sequence 7, interval 1, actual track `3190708990060870962`, and 15 relevant clock-3 snapshots with neither unit nor incremental declarations. These observations motivate a profile; they are not a new evaluator result or authenticated physical input origin.

1. **Recommended: additive source-owned V8 raw-drop profile plus a narrow evaluator.** Reuse the existing owned-file reader and ordered decoder with a new opt-in inventory hook before reset precedence. Existing V7 successful candidates already supply the instant/legacy guarantees; V8 is needed specifically for the stronger all-known-raw-drop gate, not mark encoding.
2. **Direct V7 consumer.** Smaller, but rejected after independent review: V7's sequenceStart ledger counts the state-loss branch after reset precedence. It cannot establish the required absence of unexplained raw drop declarations that coexist with reset/clear.
3. **Second owned read.** Adds I/O, identity joins, and drift/failure cases while reusing the same decoder; it provides no independent decoder verification. Reject for this scope.

`exactTwoMarkNames` is an ordered plain Array with precisely two own data entries, standard Array prototype, no proxy, accessor, hole, symbol, or extra own property beyond indices and length. Each entry is a distinct nonempty string of at most 256 UTF-8 bytes, with no Unicode control characters or ill-formed surrogate encoding. Validate descriptors before reading values; rejected getters must not execute. Position zero means start, position one means end. No inference from prefixes or filename. The caller cannot provide V7/V8 JSON, candidate rows, clocks, limits, source pins, or a policy object that weakens the profile.

Add the private package export `./internal/same-trace-interval`, pointing to the new emitted `.js`/`.d.ts`, with the existing private export's types/import/require shape. ## Additive V8 supported-header raw-drop inventory

The new read-only audit `/private/tmp/chat-ui-bench-native-stock033-b69dadc-a-raw-drop-inventory.{md,json}` reverified the retained input and found 14 nonzero previous_packet_dropped declarations: all value1, explicitly first=true, with no prior packet in the exact machine-presence/ID + sequence key. Thirteen also have sequence_flags=1 (reset); one, sequence15 packet4391, has no clear. Its strict raw classification is 14 total, 14 explained, 0 unexplained, 0 contradictions. Existing V7 remains correctly `{raw:1, explained:1, unexplained:0, contradictions:0}` for its state-loss branch. These quantities must never share an unlabeled meaning.

Add `WHOLE_USER_TIMING_V8_POLICY` (proposed fixed value `pinned-whole-trace-user-timing-raw-drop-evidence-diagnostic-v8`), `WholeUserTimingStudyV8` extending V7 with `rawDropInventory`, `createWholeUserTimingStudyV8`, `WholeUserTimingTraceV8`, and `readWholeUserTimingTraceV8`. The V8 owned reader invokes the same original descriptor read once. Its optional engine mode observes every supported known nonzero previousPacketDropped declaration before reset/stateEffect selection and before insertion of a newly seen exact scope/sequence key. This is not a new decoder or second read.

For each declaration retain packet index/body SHA256, machine presence/ID, sequence ID, raw drop value, explicit presence/value of firstPacketOnSequence, sequenceFlags and deprecated incrementalStateCleared, pre-insertion priorSeen, and classification. Classify as explained only when raw drop is exactly1, first marker explicitly true, and priorSeen=false. All other nonzero values/declarations are unexplained, including unknown bits, a missing/false first marker, and any later drop even when reset/clear coexists. Existing first-marker contradiction refusal remains effective; V8 must not turn that semantic refusal into inventory success. Explicit zero presence may be counted separately, never as a nonzero declaration or a waiver.

Retain all nonzero facts, capped at64 rows (the existing sequence cap is64); a 65th fact makes V8 unavailable even if all other input is valid. Do not raise caps or return a summary/prefix success. Charge existing persistent string, repeated work, node/string/output and 256 KiB serialization budgets before admission/append; keep the existing combined128 clock/descriptor and512 clock-entry prechecks separate and unchanged. Reuse existing closed capacity/error reasons where possible rather than expanding old failure-code membership unnecessarily.

Use `rawDropInventory` with status `complete-supported-header-declarations` or `unavailable`, a `facts` array, and `nonzeroDeclarations`, `explainedDeclarations`, `unexplainedDeclarations`, and `contradictoryDeclarations` counts. Complete counts must reconcile with every retained fact; unavailable output has empty facts and null counts, never a complete-looking partial summary. A first-marker contradiction still triggers the inherited semantic refusal, so it cannot become a completed inventory merely by incrementing a contradiction count. Pure-study complete means its full expected input was framed and supported semantics finished; the source-owned wrapper additionally requires actual EOF, closure, hash and identity before that inventory can be consumed as full-file evidence. Any parse, unsupported-state, cap, serialization, late semantic, read/identity/hash/EOF/close failure withdraws raw facts and candidate/clock observations and prevents an interval. Preserve nested pure-study EOF=false behavior. This inventory makes no claim of physical capture completeness, globally exhaustive unknown-schema semantics, or runtime/source/target/presentation authority.

## Admission algorithm: finish all checks before subtraction

1. Validate policy and mark-name boundary, then invoke source-owned V8 exactly once. Require its fixed V8 policy and type, top-level complete status, null reason, `fullInputVerified`, top-level `structuralContainerEOF`, reader EOF/close/identity/hash success, complete study framing, `semanticProcessing === 'complete-supported-schema'`, `markInventoryAdmission === 'resolved-supported-roots'`, and complete supported evidence and raw-drop inventories. Cross-check reader and study input bytes/hash. Nested pure-study `physicalEOF` and `structuralContainerEOF` deliberately remain false; neither is a rejection condition or a field to change.
2. Reject withheld candidates or withheld root inventories, old semantic sequence-start contradictions/unexplained state loss, and any V8 raw inventory unexplained or contradictory declaration anywhere in the supported input, including outside the named pair. Check complete raw facts and their exact count/classification agreement; the old V7 ledger is insufficient. Initial raw drop is explained only by value1 + explicit first=true + no previously observed exact machine/sequence key; reset/clear cannot waive a later raw drop. Proposed interval reason `raw-drop-unavailable` distinguishes absent/incomplete inventory and `unexplained-raw-drop` distinguishes failed classification from the inherited semantic failure. Existing decoder/budgets remain effective; no prefix/sample or summary-only fallback can replace full supported inventory.
3. Find exactly one literal candidate for each requested name across the complete candidate set. Reject zero or multiple matches, including duplicate names in another scope; unrelated fully resolved names do not by themselves disqualify the named pair. Require valid integer packet/event bounds/body hashes, supported representation, raw timestamp, explicit packet clock selection 3, nonzero resolved actual track, present nonzero sequence ID, and identical sequence index/ID and intervalVersion. Both candidates must have absent machine namespace in this first profile. Reject present/mixed namespaces for the named pair. Equal resolved tracks are sufficient even if selected from defaults; explicit clock 3 overrides sequence default 64.
4. Inspect every evidence row, not the first matching snapshot or only pre-mark rows. In the pair's absent machine namespace require at least one clock-3 snapshot entry, canonical uint64 absolute timestamp on every relevant clock-3 entry, and absence of *both* unitMultiplierNs and isIncremental declarations. Reject even unit=1 or incremental=false declarations as outside this first profile. Clock64/65 units/incrementality do not transfer to clock3. No conversion to primary clock 6, no equal-value correlation prerequisite, and no increasing snapshot file-order requirement. Present-namespace rows do not qualify absent-namespace marks; do not assert that the bounded evidence proves global absence of machine_id in every packet.
5. Resolve the pair's track in the same machine namespace through a consistent thread descriptor and parent process descriptor. Require a nonzero parent UUID, thread PID/TID, parent PID and process start-generation timestamp, matching child/parent PID, and consistent values across all matching descriptor observations. Require an establishing matching track disclosure in the candidate's sequence index/ID and interval at or before the first mark. A matching parent process declaration may occur on another sequence in the same machine namespace, as builtin-domain identity is not sequence-local. Reject missing/ambiguous parent identity, process-and-thread ambiguity on a single identity, contradictory UUID/parent/PID/TID/start-generation reuse anywhere in matching evidence, and incompatible candidate/scoped descriptor namespaces. Repeated identical declarations are acceptable. Process start is an opaque generation component: never compare it chronologically to clock-3 event time without a separately established clock mapping.
6. Parse timestamps only after canonical unsigned decimal-string validation and uint64 bounds (`0` through `18446744073709551615`), using BigInt. Check name-order packet positions and require end timestamp strictly greater than start. Then subtract with BigInt and emit its exact decimal string. No Number conversion, frame counting, rate conversion, or interval value in this design pass.

Do not claim the V7 projection proves there were no intervening defaults updates: it does not expose that history exhaustively as an event list. Explicit clock3 selection and the pair's same resolved track and reset interval supply the needed narrow selection invariant. Unresolved/corrupt default state remains a rejection through V7 and candidate checks. Source-owned EOF does not prove capture/source completeness or target lifecycle.

## Result and bounded witness

Return a fixed discriminated diagnostic result with policy, status (`same-trace-clock3-interval-diagnostic` or `unavailable`), a closed reason code or null, `traceIntervalNs`, `durationNs:null`, `inputOrigin:'not_authenticated'`, and fixed authority labels. Rejections always have null interval and no partial success witness. Bound invalid-argument output independently of attacker strings; do not echo paths or arbitrary rejected values.

A successful witness contains exactly two selected mark identities with packet indices, event bounds, body hashes and raw timestamps; input byte count/SHA256 and bounded reader facts; packet and transition manifest hashes; fixed compatibility record identity and both source pins; V8 raw nonzero/explained/unexplained/contradiction counts labeled separately from old semantic sequenceStart counts; same-domain namespace/sequence/reset interval/actual track; scoped thread/parent/PID/TID/process-start-generation identity; and counts of examined/relevant snapshots and descriptors. Copy no unbounded V7/V8 JSON, anchors, diagnostics, or observation arrays. Existing limits (128 combined evidence rows, 512 clocks, 128 candidates, 16384 candidate UTF8, existing persistent/output budgets) are not enlarged; V8 adds a separate64-fact raw inventory inside those shared byte/work budgets. Use a fixed maximum interval-output UTF8 size (proposed16 KiB) checked before return, fixed tuple/cardinality fields, and owned frozen output. Never truncate a witness into apparent success.
