# Hosted scroll cause diagnostic

This separate workflow retains bounded evidence about virtualizer resize decisions and scroll requests during the original strict Tracker A scenario. Every result remains unqualified: `qualification`, `nativeGO`, and `performance` are false, and FPS is unavailable. A request ledger is not proof of a browser scroll, continuous anchoring, throughput, or causality. Original strict guards and the first failure are unchanged.

Dispatch `hosted-copilot-scroll-cause.yml` at the immutable `hosted-copilot-react-scroll-cause-v1` tag with `candidate_sha` equal to that tag's exact commit. The launcher requires matching checkout, Actions source/workflow SHA, repository, attempt 1, Linux, Node 24.20.0 and npm 11.19.0. It checks source before dependencies, installs the lock without scripts, and builds with a separate diagnostic Vite config. It does not accept a normal STATIC/native prerequisite or produce normal admission.

The diagnostic entry registers one observer before re-exporting the original named `launchPage`. The exact original Tanstack module receives insertion-only hooks; reverse proof, relevant physical module hashes, shared singleton/chunk mapping, original HTML launch identity and every emitted asset hash are retained. Module coverage is explicitly `diagnostic-owned-and-instrumented-modules`; the full dependency graph is unqualified. Components are physical source pins, including components that emit no module. Relevant rows are bounded at 256 and metadata at 1 MiB. The frontend archive expands to at most 64 MiB. The original nested worker runs from `apps/copilotkit/artifacts/scroll-cause/RUN-1/worker.mjs`; `diagnostic-worker.mjs` is its closed byte-exact artifact copy. The copy is never imported. Public external package/lock pins and the diagnostic five-level Zod binding are checked separately from normal worker admission.

The immutable prebuild recipe precedes build receipts and the later tracker profile. Runtime refers to the actual tracker profile. The final manifest references all three, avoiding a hash cycle. It binds literal input, transport, case, same-owner anchor, ledger and export originals when available; optional absences require explicit original witnesses. Missing files alone do not prove absence. Collection completeness and diagnostic coverage are separate from strict scenario success.

`run` captures a separate parent from spawn. The parent captures a separate application child and owns the public BrowserServer. Original stdout/stderr remain literal bounded bytes, including SDK stacks. Derived errors use closed codes. A bounded child footer, emitted after role writers close, joins source/run, raw-sink creation/closure and the strict-result hash to the exact captured application stdout. Browser metadata describes post-bind public stream coverage; executable byte identity and descendants remain unqualified. Original browser close promise/event and each attached stream/sink close are distinct witnesses. No protocol pipe is read or written.

A fully closed strict refusal exits 2 through child, parent and outer run, preserving failure. Infrastructure, write, fsync, import, overflow or closure refusals exit 1 and cannot be admitted by inventory. Inventory runs in a later workflow step after outer run returned, including after strict failure. It authenticates the fixed 31-role flat namespace, literal references, whole hashes, single-link regular files, descriptor/path identities, stream byte joins and actual allowed exits. Aggregate original worker plus artifact roles stay within 128 MiB and 128 files; the fixed maxima reserve 121,245,696 bytes and 32 files. No arbitrary directory is uploaded.

The manifest is written last, fsynced and read back. Original namespace/hashes are rechecked after that write and by a separate finalcheck immediately before upload. A physically existing manifest after an interrupted or refused action grants no upload; workflow inventory and finalcheck exits must both succeed. This is bounded pre/post filesystem observation, not continuous filesystem surveillance or a full production admission replay.

`npm run typecheck:scroll-cause` checks all new diagnostic entry/config/helper/CLI/test sources under strict settings and the existing Copilot vendor declaration policy. Default tests remain SDK/browser-free. `npm run test:scroll-cause:build` explicitly runs the actual Vite build, original HTML/context request in Chromium, actual BrowserServer closure and final nested worker import with no `NODE_PATH`; it stops before native scenario invocation and labels working-tree inputs as LOCAL_TEST, never clean hosted source. The separate hosted diagnostic runs only after reviewed source is merged and its original CI is green.
